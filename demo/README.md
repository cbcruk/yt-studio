# 플레이그라운드

설치하지 않고 `ytstudio` 를 만져 보는 페이지. 에디터에 코드를 쓰면 옆에서
명령어가 만들어지고, 그 명령어를 곧바로 검사해서 보여 준다.

```
bun install
cd .. && bun run build && cd demo    # 데모는 lib/ 를 읽는다
bun run dev
```

## 왜 손으로 적은 목록이 하나도 없나

이 페이지가 하는 주장은 하나다 — **여기 뜨는 자동완성이 `npm i ytstudio` 한
사람의 에디터에 뜨는 것과 같다.** 그 주장을 지키려면 목록을 여기서 다시 만들면
안 된다. 그래서 세 가지를 저장소에서 그대로 가져온다.

| 무엇 | 어디서 | 왜 |
|---|---|---|
| 자동완성·마우스오버 | `lib/**/*.d.ts` | `tsc` 가 뱉은 것 그대로를 브라우저 안 타입스크립트에 먹인다 |
| 검사·설명·빌더 | `lib/browser.js` | 배포하는 모듈이 브라우저에서 그대로 돈다 |
| 옵션 카탈로그 | `ytstudio.schema.json` | 설치된 yt-dlp 를 리플렉션한 그 한 벌 |

그래서 `bun run build` 가 선행이다. 소스(`src/`)를 바로 읽지 않는 것도 같은
이유다 — 손님이 받는 것은 재료가 아니라 산출물이다.

## 무엇을 어떻게 쓰나

* **monaco** — 에디터이면서 타입스크립트 언어 서비스다. 자동완성·마우스오버·
  오류가 진짜 타입 검사에서 나오고, 같은 워커가 트랜스파일까지 한다
  (`getEmitOutput`). 컴파일러를 따로 얹지 않는다.
* **평가** — 트랜스파일한 것을 `new Function` 으로 부른다. 손님 브라우저에서
  손님 코드가 도는 것이라 서버로 나가는 것이 없다.
* **`ytstudio/browser`** — 파일 시스템을 안 보는 입구. 본체(`ytstudio`)가 노드에
  묶이는 부분은 "스키마를 어디서 집을까" 한 겹뿐이라, 그걸 걷어낸 것이다.

## 확인

```
bun run check     # 타입
bun run build
bun run smoke     # 크로미움을 띄워서 본다
```

`smoke.ts` 가 보는 것은 **브라우저 안에서만 보이는 것들**이다 — 가상 파일
시스템에 얹은 `.d.ts` 를 타입스크립트가 실제로 풀어냈는지, 자동완성 목록에
`embedThumbnail` 이 뜨는지, 마우스오버에 yt-dlp 의 설명문이 오는지, 손님 코드가
명령어를 거쳐 검사까지 가는지. 모듈 해석이 어긋나면 목록이 통째로 비는데
화면은 멀쩡해 보이므로, 눈으로는 못 잡는다.
